## Summary

Move the curve-shaping vocabulary into `vxn-core-matrix` and have both synths
use it. This is the duplication that prompted
[E049](../../epics/closed/E049-shared-matrix-routing.md): commits `bbff167` and
`868faef` added the same design to each synth by hand, 96 minutes apart.

Moving, in both directions from one shared definition:

- `Polarity` {Direct, Bipolar, Abs} and `Shape` {Lin, Exp, Log}, with their
  name/label tables and `from_u8`.
- The polarity maps (`v`, `2v−1`, `|v|`) and shape bends (`v`, `sign(v)·v²`,
  `sign(v)·√|v|`).
- `curve_code` / `curve_split` and the flat `CURVE_NAMES` preset table,
  including the legacy-spelling guarantee that codes 0..3 mean
  `lin`/`exp`/`log`/`bipolar`.
- `scale_norm`: the fold-by-source-polarity, clamp, then bend — plus
  `clamp_unit` and its documented `max/min`-not-`clamp` reasoning.

Compare
[vxn-2 matrix.rs](../../vxn-2/crates/vxn2-engine/src/matrix.rs) §Polarity/Shape
against [vxn-1b matrix.rs](../../vxn-1b/crates/vxn1b-engine/src/matrix.rs)
§Polarity/Shape: same enums, same discriminants, same codes, same tables. The
only real difference is that vxn-1b's are generated by `matrix_enum!` and
vxn-2's are hand-written.

## Design

Take vxn-1b's generated form as the canon — `matrix_enum!` moves to the shared
crate with the enums, and vxn-2 stops hand-maintaining its parallel lists. The
generated form makes a transposed name/label pair unrepresentable, which the
hand-written form only length-checks.

The bends stay free functions, not trait methods or closures: they are dispatched
once per slot into straight-line lane loops, and
[[vxn2-matrix-hot-loop-lessons]] records that this loop is unforgiving —
`copysign` lost to the branch it replaced, and `f32::clamp`'s panic path cost
~7%. Keep `clamp_unit`, keep the branch in `shape_log`, and **re-measure rather
than trusting either** after the move: LTO across a crate boundary is not the
same inlining problem as within one.

## Acceptance criteria

- [ ] Both synths import the axes, the codec and `scale_norm` from
      `vxn-core-matrix`; neither defines its own.
- [ ] `matrix_enum!` lives in the shared crate; vxn-2's hand-written source/dest
      name and label tables are generated by it too (that is the natural
      consequence of moving the macro, and is a strict improvement).
- [ ] `curve_code(Bipolar, Lin) == 3` and `CURVE_NAMES[3] == "bipolar"` still
      hold — the legacy preset encoding is load-bearing in both synths.
- [ ] Every factory preset in both synths still loads with no warnings.
- [ ] Both render-hash baselines **byte-identical** — one of the two tickets
      held to that (see [E049](../../epics/closed/E049-shared-matrix-routing.md)
      §"The bar"). Nothing here reorders an arithmetic operation; code changes
      crate, that is all. A moved bit means something was mistranscribed.
- [ ] `matrix_eval_full` / `matrix_eval_scaled` (vxn2-osc-bench) within noise of
      their pre-ticket numbers, or the regression is explained and accepted in
      the close-out.

## Notes

- Lowest-risk slice in the epic and the one with the clearest payoff: it is the
  code that was literally written twice this week.
- **`clamp_unit` exists only in vxn-2 today** — vxn-1b's `scale_norm` uses plain
  `n.clamp(0.0, 1.0)`, panic path and all. Unifying on `clamp_unit` is the right
  call, but it is the one piece of this ticket that is not pure movement for
  vxn-1b: results are identical for finite inputs (so the byte-identical
  criterion stands), but NaN saturates under `max`/`min` where `clamp`
  propagates it, and the instruction sequence changes. Say so in the close-out.
- No layout dependency — this can land before
  [0328](0328-matrix-dest-major-lane-accumulators.md).
- Out of scope: the slot type, route compilation, the evaluator. Vocabulary
  only.

## Close-out (2026-08-31)

- The vocabulary lives in [`vxn-core-matrix/src/curve.rs`](../../crates/vxn-core-matrix/src/curve.rs)
  (~600 lines): the `Polarity`/`Shape` axes and their name/label tables,
  `from_u8`, the polarity maps and shape bends, `curve_code` / `curve_split` /
  `CURVE_NAMES` / `CURVE_LABELS`, `clamp_unit`
  ([curve.rs:375](../../crates/vxn-core-matrix/src/curve.rs#L375)) and
  `scale_norm` ([curve.rs:460](../../crates/vxn-core-matrix/src/curve.rs#L460)).
  Neither synth defines any of it; both re-export.
- `matrix_enum!` moved to [curve.rs:74](../../crates/vxn-core-matrix/src/curve.rs#L74),
  `#[macro_export]`ed with `$crate::` recursion so it works cross-crate. vxn-2's
  `SourceId` and `DestId` are generated by it —
  [matrix.rs:231](../../vxn-2/crates/vxn2-engine/src/matrix.rs#L231) and
  [matrix.rs:292](../../vxn-2/crates/vxn2-engine/src/matrix.rs#L292) — retiring
  five hand-kept parallel lists. `PolarityKind`/`ShapeKind` renamed to
  `Polarity`/`Shape`, 326 occurrences across 9 files. Net −630 lines of source.
- Legacy preset encoding holds: `curve::tests::curve_code_preserves_pre_split_encoding`
  and `curve_code_round_trips_every_pair` pass in the shared crate, and both
  synths' own `curve_code_preserves_pre_split_*` tests still pass.
- Factory presets clean in both synths: `factory::tests::every_factory_preset_parses_cleanly`,
  `every_factory_preset_parses_without_warnings`, `every_factory_preset_round_trips`,
  `no_factory_preset_has_a_half_wired_slot`, `no_factory_preset_routes_incoherently`.
- **Render hashes byte-identical.** vxn-1b passes `render_hash_unchanged` in
  debug under `VXN_RENDER_HASH=1`. vxn-2 reproduces `EXPECTED`
  (`0x9b7678e7f9d3534b`) byte-for-byte under `--release`; its debug value on this
  box is `0x95ac9a59d27aaddd`, exactly the constant
  [baseline.rs:41-44](../../vxn-2/crates/vxn2-engine/tests/baseline.rs#L41)
  documents for the debug profile — pre-existing profile sensitivity, not this
  change. Null tests `-inf dBFS` on both synths: bit-identical renders, which is
  what pure movement should look like.
- Benches within noise, as required: `matrix_eval_full` 140.98 → 138.25 ns,
  `matrix_eval_scaled` 125.76 → 123.84 ns, `matrix_eval_empty` 26.82 → 26.63 ns.
  Criterion reports "No change in performance detected" on all three — crossing
  the crate boundary did not cost the inlining. (Measured before the serialised
  bench window; the after-run sat at load ~20, which biases slow, so "no
  regression" is the conservative reading.)
- **The one behaviour change, as the ticket predicted.** vxn-1b's `scale_norm`
  moves from `n.clamp(0.0, 1.0)` to `clamp_unit`. Identical on every finite
  input — hence the `-inf` null — but on NaN `clamp_unit` returns `0.0`, shutting
  the VCA gate, where `clamp` propagates and poisons the dest accumulator for the
  whole block. The emitted instruction sequence changes with it. Covered by
  `curve::tests::clamp_unit_saturates_and_swallows_nan`.
- **Two judgement calls beyond the ticket's file list.** `CURVE_LABELS` moved
  even though it is vxn-2-only today — it is `CURVE_NAMES`' twin and the pair is
  exactly what kept drifting. And `scale_norm` takes `bipolar: bool` rather than
  a `SourceId`, because the shared crate deliberately cannot know a source id;
  each synth reads `.is_bipolar()` at the call site. That prefigures
  `MatrixRoster::source_is_bipolar` and is an API decision
  [0333](0333-share-slot-and-route-compilation.md) / [0334](0334-share-the-evaluator.md)
  inherit.
- **A third copy was found and folded in.** vxn-1b's bank evaluator had the curve
  arithmetic inlined again in local closures — not in this ticket's file list. It
  now uses the shared arms
  ([bank.rs](../../vxn-1b/crates/vxn1b-engine/src/bank.rs)).
- The stale `shape_log` comment claiming "`copysign`, not a branch" over a body
  that *is* a branch was corrected rather than transcribed. `DestId`'s
  discriminants went from implicit to 52 explicit numbers, so vxn-1b's
  `variant_order_matches_the_tables` and a
  `names_and_labels_describe_their_own_variant` spot-check were ported into vxn-2
  to keep density and order asserted.
- Landed via `e049/0330-curve-vocab` @ `d924b9c`, merged to `main` in `c58167c`.
